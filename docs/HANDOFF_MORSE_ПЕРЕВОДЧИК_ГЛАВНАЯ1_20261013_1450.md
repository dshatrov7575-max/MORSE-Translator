## Решение владельца по uz/tj и его реализация

Владелец выбрал вариант 2 из открытого вопроса v8: **сознательно
ограничить MVP** — распознавание речи для узбекского/таджикского не
включается в первую версию продукта (а не выдаётся с низким качеством под
видом рабочей функции).

Реализовал сразу в коде (та же логика, что уже применена к /check,
/to_umr, /from_umr — честная ошибка вместо выдуманного/плохого
результата):

1. `morse-core/app/main.py`, `/asr`: новый необязательный form-параметр
   `lang`. Если `uz`/`tj` — сразу 503 с понятным объяснением и ссылкой на
   отчёт, без траты времени на распознавание. Если язык не передан и
   Whisper сам определит `uz`/`tg` (важно: код Whisper для таджикского —
   `tg`, не `tj` из нашей схемы!) — та же честная ошибка вместо тихой
   выдачи мусора.
2. `gradio-app/app.py`: при выборе узбекского/таджикского как языка ввода
   поле микрофона становится неактивным с понятной подписью — обработчик
   `source_lang.change(toggle_mic, ...)`.
3. Отчёт о проверке речи (`MORSE_SPEECH_CHECK_UZ_TJ_D0_20261013.md`)
   дополнен разделом «Решение владельца» с описанием реализации.
4. Синтаксис обоих изменённых файлов проверен (`py_compile`), закоммичено
   и запушено (коммит `e94d0df`).
