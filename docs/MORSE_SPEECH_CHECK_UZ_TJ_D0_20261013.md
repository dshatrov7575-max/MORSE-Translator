# Проверка речи (uz/tj) — MORSE-переводчик(нейро), этап D0 (13.10.2026)

## Важное изменение источника данных

Common Voice с октября 2025 года **полностью убран с HuggingFace** — Mozilla
перевела датасет исключительно на свою новую платформу
[Mozilla Data Collective](https://datacollective.mozillafoundation.org)
(страница датасета на HF теперь просто заглушка с уведомлением об этом).
Путь из исходного плана («скачать Common Voice через HuggingFace без
email-гейта») больше не работает в принципе — не только для этой
облачной сессии, но и вообще откуда угодно без аккаунта на новой
платформе.

**Замена:** датасет **FLEURS** (Google, `google/fleurs` на HuggingFace) —
открытый, без гейта, покрывает 102 языка, включая узбекский (`uz_uz`) и
таджикский (`tg_tj`), с эталонными текстовыми транскрипциями. Это
стандартный открытый бенчмарк для ASR, не хуже Common Voice для целей
такой проверки.

## Методика

- Машина: LM-STUDIO (обычный интернет, в отличие от этой облачной сессии).
- Взято по 10 коротких фраз из тестовой выборки `uz_uz` и `tg_tj`
  (потоково, без скачивания полного датасета — только нужные строки через
  `datasets` с `streaming=True`).
- Распознавание: `faster-whisper` `large-v3-turbo`, CPU, `compute_type=int8`
  (та же модель, что уже встроена в `morse-core/app/main.py`, эндпоинт
  `/asr`), без дополнительной настройки под язык.
- Сравнение: эталонный текст (latin-орфография для uz, кириллица для tg)
  против вывода модели.
- Полные необработанные результаты (все 20 пар эталон/распознано):
  `docs/data/asr_results_uz_tg_20261013.json`.

## Результат: faster-whisper плохо справляется с uz/tj

**Узбекский.** Распознавание почти везде даёт не настоящий узбекский текст,
а фонетически похожую, но исковерканную кириллицу (похожую скорее на
казахскую орфографию, чем на узбекскую) — то есть модель даже не
воспроизводит правильную латинскую орфографию узбекского. 2 из 10 образцов
дали полный сбой: один — зацикливание (повтор одного и того же слога ~90
раз подряд), другой — вывод на тибетском письме, никак не связанный со
входом (классическая галлюцинация Whisper на языке с низким ресурсом).
Язык детектируется правильно (`uz`, вероятность 1.0) — но это не помогает
качеству самого текста.

**Таджикский.** Чуть осмысленнее по структуре слов, но модель почти везде
соскальзывает в персидское (арабское) письмо или в произвольную
латинскую транслитерацию вместо кириллицы, в которой на самом деле
написан таджикский. Полных сбоев (зацикливание/галлюцинация) в этой
десятке не было, но ни один из 10 ответов не является пригодным
распознаванием — смысл не восстановить без знания исходного текста.

**Вывод:** в текущем виде (`faster-whisper large-v3-turbo` без
дополнительной настройки) распознавание речи для узбекского и
таджикского **непригодно для продукта**. Это не баг кода — так ведёт
себя сама модель на низкоресурсных языках. Для русского и английского
(прежние эндпоинты не тестировались в этом проходе, но модель на них
исторически работает хорошо) это не проблема.

## Что это значит для плана

Раздел плана, предполагавший единый ASR-движок (faster-whisper) на все
4 языка, нуждается в пересмотре для uz/tj. Варианты:

1. **Попробовать Meta MMS** (`facebook/mms-1b-all`, HuggingFace
   `transformers`) — модель, специально обученная на ~1100 языках, включая
   узбекский и таджикский, обычно существенно сильнее Whisper на
   низкоресурсных языках. Не тестировалось в этом проходе — следующий
   логичный шаг.
2. Принять ограничение: on uz/tj распознавание речи либо недоступно в
   MVP, либо доступно с явной пометкой «экспериментально, низкое
   качество», и фокус для этих языков — на текстовый ввод.
3. Дообучение/fine-tuning Whisper под uz/tj — заметно дороже по времени,
   не укладывается в темп D0.

## Решение владельца (13.10.2026)

Выбран вариант **2**: распознавание речи для узбекского и таджикского
сознательно исключается из MVP (а не выдаётся с низким качеством под
видом рабочей функции). Реализовано в коде:

- `morse-core/app/main.py`, эндпоинт `/asr`: принимает необязательный
  `lang` (form-поле); если `uz`/`tj` — сразу честная ошибка 503 с
  объяснением и ссылкой на этот отчёт, без траты времени на распознавание.
  Если язык не передан и Whisper сам определит `uz`/`tg` (код Whisper для
  таджикского — `tg`, не `tj`!) — та же честная ошибка вместо выдачи
  результата.
- `gradio-app/app.py`: при выборе узбекского/таджикского как языка ввода
  поле микрофона становится неактивным с пояснением, вместо того чтобы
  пускать пользователя на заведомо нерабочий запрос.
